# 1.1 Import Entry Point Inventory

## 1. Purchase Import (`PurchaseImportService`)
- **Marker Policy**: Parses and removes leading `* ` (asterisk) and trailing ` TP` markers to extract the `clean_name`.
- **Creation Defaults**:
  - `product_cost`: 0
  - `product_price`: 0
  - `product_quantity`: 0
  - `stock_managed`: 1
  - `is_purchased`: 1
  - `is_sold`: 1
  - `product_note`: Extracted from description
  - `product_code`: Uses imported code if available, otherwise generates a `SKU-...` fallback
  - `unit_id` / `base_unit_id`: Dynamically created or found based on parsed unit name.
  - `setting_id`: Determined by the import context/marker.

## 2. Sales Import (`SalesImportService`)
- **Marker Policy**: Uses `SalesImportMarkerResolver` which parses and removes leading `* ` (asterisk) and trailing ` TP` markers to extract the `clean_name`.
- **Creation Defaults**:
  - `product_cost`: 0
  - `product_price`: 0
  - `product_quantity`: 0
  - `stock_managed`: 1
  - `is_purchased`: 1
  - `is_sold`: 1
  - `product_note`: Extracted from description
  - `product_code`: Generated via `importProductCode`
  - `unit_id` / `base_unit_id`: Dynamically created or found based on parsed unit name.
  - `setting_id`: Determined by the marker (e.g. `*` -> PT. KJA).

## 3. Product CSV Import (`ProcessProductImportChunk`)
- **Marker Policy**: No marker parsing. It just trims the raw name `trim((string) ($p['product_name'] ?? ''))`. Rejects explicitly if name is duplicated in DB.
- **Creation Defaults**:
  - Reads values directly from CSV: `category_id`, `brand_id`, `unit_id`, `stock_managed`, `product_stock_alert`, `product_quantity`, `is_purchased`, `is_sold`.
  - `product_code`: From CSV or null.
  - `product_price`: Set to default 0 (legacy price fields).
  - `product_cost`: Set to default 0.

## 4. Non-Creating Imports (Sales-price, Stock snapshot, Dual-company tier-price)
- **Marker Policy**: Stock and HPP snapshot likely just match the raw/cleaned name. Dual-company tier-price matches existing products by name.
- **Creation Defaults**: None. These paths *only* resolve existing products and do not create them, matching the decision to use `resolveExisting` in the future.
