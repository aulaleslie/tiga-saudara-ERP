# Proposal

## Why

After an authorized monetary edit to a Sale generated by POS, global POS payment uses the corrected Sale total and live due, but receipt reprints still show checkout-time prices and debt. Customers can therefore receive a reprint whose amount differs from the amount being collected.

## What Changes

- Persist a direct association from each generated Sale detail to its originating POS transaction line for new checkouts, including owner-split bundle allocations.
- Project completed receipt reprints from the latest linked Sale monetary values at the corresponding customer-facing POS lines. A bundle remains one priced parent line; its current amount includes the linked owner Sale detail contributions without billing nested component rows again.
- Keep the existing receipt layout, product/quantity/serial/composition presentation, and checkout-time tender and change facts. Show the current Sale-derived total and live `Sisa Utang` from the same settlement source as global POS payment.
- For historical checkouts without direct links, use a mapping only when its line assignment is provable. If a multi-line assignment is ambiguous, do not issue an updated-price reprint or silently place an amount on the wrong line; give the operator an actionable explanation and preserve access to the original checkout receipt.
- Keep Sale monetary editing rules and internal bundle-item allocation snapshots unchanged.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `pos-checkout-split-posting`: Persist POS line provenance for every generated Sale detail, including split bundle groups.
- `pos-receipt`: Reprint current line and transaction monetary amounts using proven provenance, with safe handling of ambiguous historical records.
- `global-pos-multi-payment`: Show live `Sisa Utang` on updated reprints while preserving original tender and change history.

## Impact

Touches additive POS/Sale detail lineage storage, POS checkout posting, completed receipt projection, and all completed receipt reprint entry points that use it. Global payment settlement and Sale monetary edit services remain the monetary authorities. Verification is focused automated tests plus human developer browser checks; no full-suite or automated browser run is planned.
