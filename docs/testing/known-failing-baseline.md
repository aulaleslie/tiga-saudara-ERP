# Known-failing baseline (repository-wide)

This list is **tracking, not an exclusion mechanism**: every test below stays enabled in `phpunit.xml` and still fails the default run.
The consignment-related paths are verified separately (see the "Verified consignment baseline" section).

## Verified consignment baseline

`bash scripts/test-consignment-baseline.sh` runs the dedicated Consignment suite plus every other test file that references consignment (listed in `phpunit.consignment.xml`) and the isolation probe. Result when generated: **Tests:    741 passed (3231 assertions)**. None of the consignment-referencing files appear in the failing list. It does **not** make the repository-wide suite green and says nothing about MySQL concurrency.

## Decisions

Settled:

1. **Payment-status values.** The `Purchase::PAYMENT_STATUS_*` constants are canonical (`Paid`, `Partial`, `Unpaid`), with historical casing compatibility preserved. The ~20 tests asserting `PAID`/`UNPAID` (`PurchaseImportPaymentLedgerTest`, `PurchaseReturnSettlementLogicTest`, ...) are therefore stale; deferred because they are not consignment-affecting.
2. **Permission names.** `purchases.update` and `purchases.receive.access` are canonical. `PurchaseAuthorizationTest` asserts both that they exist and that they do not, and is stale; deferred.
3. **Unauthorized purchase status change** returns HTTP 403 with no mutation (implemented in `PurchaseController::updateStatus`; ordinary transition and consignment-guard errors keep their error-toast handling).
4. Eligible cross-setting stock-opname locations are allowed; inactive, nonexistent and consignment locations stay rejected. Cross-setting audit viewing requires `adjustments.show` and keeps stock redaction.

Open (consignment):

- **POS provenance for non-split checkouts.** A single-setting POS checkout links its sale only through `pos_checkouts.sale_id` and writes no `pos_checkout_sales` row; sold-source discovery (and the billing-confirmation lifecycle) resolve POS provenance only through `pos_checkout_sales`. So sold sources from non-split POS checkouts have `pos_checkout_id = null`. `pos_checkout_id` is part of the versioned source snapshot, so changing this is a deliberate decision, not a silent fix. `ConsignmentPosCheckoutDiscoveryTest` pins the current behavior; flip its assertion when decided.

## Test isolation notes

- `PreservesMigrationSeededTables` (used by the two `DatabaseTruncation` Pos classes) excludes `cash_denominations`, `payment_terms` and `permissions` from truncation and restores their rows after every test.
- `ResetsSqliteAutoIncrement` is used by the three tests that commit the wrapping transaction and hand-delete rows (`CashDrawerAfterCommitRetryTest`, `DocumentSequenceAllocatorTest`, `PosCheckoutLedgerDeadlockRetryTest`). Removing fixed-ID assumptions everywhere is not practical (193 test files hardcode `default_currency_id => 1`), so the polluters rewind what they commit.
- Never run two test processes against `database/testing.sqlite`; use `composer test:fresh-sqlite` / `scripts/test-with-fresh-sqlite.sh`.
